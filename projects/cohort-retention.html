01 The Growth Paradox: Expanding Volume, Vanishing Margins

In high-velocity e-commerce and FinTech platforms, monthly revenue graphs often tell a misleading story. During major promotional periods (such as April Festive/Eid sales and November 11.11 mega-campaigns), customer acquisition surges. Management celebrates top-line user additions, but unit contribution margins silently collapse.

The Core Dilemma: Are newly acquired users building sustained repeat purchasing habits, or is the platform simply subsidizing one-and-done discount hunters? Without granular cohort tracking and channel-specific LTV-to-CAC modeling, growth capital is poured into leaky buckets.

Investigation Mandate: Using production ANSI SQL on an enterprise relational SQLite warehouse, conduct a full unit-economics audit:

  • Measure 12-month cohort retention decay rates (M0 to M11).
  • Calculate Net Revenue Retention (NRR) and evaluate whether retained users demonstrate Average Order Value (AOV) expansion.
  • Evaluate customer acquisition unit economics (CAC, LTV, Gross Profit, ROI) across Meta Ads, Google Search, Organic Search, and Referrals.
  • Map the exact day-latency between first and second orders to isolate the platform's churn cliff.

03 Production SQL Query Suite

Below are the optimized SQL scripts engineered to compute cohort dynamics, Net Revenue Retention, channel profitability, and repurchase latency:

1. Monthly Cohort Retention Matrix (User Decay Pivot)

Pivots Month 0 to Month 11 Decay 
-- STEP 1: Compute Cohort Base Size
WITH cohort_sizes AS (
    SELECT cohort_month, COUNT(DISTINCT user_id) AS total_cohort_users
    FROM users GROUP BY cohort_month
),
-- STEP 2: Count Retained Active Buyers Per Month Index
monthly_retention AS (
    SELECT 
        o.cohort_month,
        o.cohort_index,
        COUNT(DISTINCT o.user_id) AS retained_users
    FROM orders o
    WHERE o.status = 'Delivered'
    GROUP BY o.cohort_month, o.cohort_index
),
-- STEP 3: Calculate Retention Decay Percentage
retention_decay_curve AS (
    SELECT 
        r.cohort_month,
        s.total_cohort_users AS cohort_size,
        r.cohort_index,
        r.retained_users,
        ROUND((r.retained_users * 100.0) / s.total_cohort_users, 2) AS retention_rate_pct
    FROM monthly_retention r
    JOIN cohort_sizes s ON r.cohort_month = s.cohort_month
)
-- STEP 4: Executive Matrix Pivot Presentation
SELECT 
    cohort_month,
    cohort_size AS m0_cohort_size,
    MAX(CASE WHEN cohort_index = 1  THEN retention_rate_pct END) AS m1_pct,
    MAX(CASE WHEN cohort_index = 2  THEN retention_rate_pct END) AS m2_pct,
    MAX(CASE WHEN cohort_index = 3  THEN retention_rate_pct END) AS m3_pct,
    MAX(CASE WHEN cohort_index = 6  THEN retention_rate_pct END) AS m6_pct,
    MAX(CASE WHEN cohort_index = 11 THEN retention_rate_pct END) AS m11_pct
FROM retention_decay_curve
GROUP BY cohort_month, cohort_size
ORDER BY cohort_month ASC;

2. Net Revenue Retention (NRR) & Cumulative LTV Window Function

Running Sum + AOV Tracking 
WITH cohort_baseline AS (
    SELECT 
        cohort_month,
        COUNT(DISTINCT user_id) AS total_users,
        ROUND(SUM(net_revenue), 2) AS m0_revenue
    FROM orders
    WHERE status = 'Delivered' AND cohort_index = 0
    GROUP BY cohort_month
),
monthly_cohort_revenue AS (
    SELECT 
        o.cohort_month,
        o.cohort_index,
        COUNT(DISTINCT o.user_id) AS active_spenders,
        ROUND(SUM(o.net_revenue), 2) AS monthly_revenue,
        ROUND(AVG(o.net_revenue), 2) AS monthly_aov
    FROM orders o
    WHERE o.status = 'Delivered'
    GROUP BY o.cohort_month, o.cohort_index
)
SELECT 
    m.cohort_month,
    m.cohort_index,
    m.active_spenders,
    m.monthly_revenue,
    m.monthly_aov,
    -- Net Revenue Retention % (Spend vs Month 0)
    ROUND((m.monthly_revenue * 100.0) / b.m0_revenue, 2) AS nrr_pct,
    -- Running Cumulative Revenue via Window Function
    ROUND(SUM(m.monthly_revenue) OVER (
        PARTITION BY m.cohort_month 
        ORDER BY m.cohort_index 
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ), 2) AS cumulative_revenue,
    -- Cumulative LTV per initial customer
    ROUND(SUM(m.monthly_revenue) OVER (
        PARTITION BY m.cohort_month 
        ORDER BY m.cohort_index 
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) / b.total_users, 2) AS cumulative_ltv_per_user
FROM monthly_cohort_revenue m
JOIN cohort_baseline b ON m.cohort_month = b.cohort_month;

3. Marketing Acquisition Economics (Channel CAC vs LTV & Net ROI)

Gross Margin & ROI Computation 
WITH channel_users AS (
    SELECT 
        u.acquisition_channel,
        COUNT(DISTINCT u.user_id) AS total_acquired_users,
        ROUND(c.blended_cac_usd * 120.0, 2) AS cac_bdt,
        ROUND(COUNT(DISTINCT u.user_id) * c.blended_cac_usd * 120.0, 2) AS total_marketing_spend_bdt
    FROM users u
    JOIN channel_cac_benchmarks c ON u.acquisition_channel = c.channel_name
    GROUP BY u.acquisition_channel, c.blended_cac_usd
),
channel_revenues AS (
    SELECT 
        u.acquisition_channel,
        ROUND(SUM(o.net_revenue), 2) AS gross_revenue_bdt,
        ROUND(SUM(o.net_revenue) * 0.35, 2) AS gross_profit_bdt
    FROM orders o JOIN users u ON o.user_id = u.user_id
    WHERE o.status = 'Delivered'
    GROUP BY u.acquisition_channel
)
SELECT 
    u.acquisition_channel,
    u.total_acquired_users,
    u.cac_bdt,
    ROUND(r.gross_profit_bdt / u.total_acquired_users, 2) AS ltv_gross_profit,
    -- LTV to CAC Ratio
    ROUND((r.gross_profit_bdt / u.total_acquired_users) / u.cac_bdt, 2) AS ltv_to_cac_ratio,
    -- Marketing Net Contribution & ROI
    ROUND(r.gross_profit_bdt - u.total_marketing_spend_bdt, 2) AS net_contribution_bdt,
    ROUND(((r.gross_profit_bdt - u.total_marketing_spend_bdt) * 100.0) / u.total_marketing_spend_bdt, 2) AS marketing_roi_pct
FROM channel_users u
JOIN channel_revenues r ON u.acquisition_channel = r.acquisition_channel
ORDER BY ltv_to_cac_ratio DESC;

4. Churn Cliff & Repurchase Latency Interval Audit

Julian Day Date Diff & Sequencing 
WITH ordered_customer_history AS (
    SELECT 
        user_id, order_id, order_date,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date ASC) AS order_seq
    FROM orders WHERE status = 'Delivered'
),
first_and_second_orders AS (
    SELECT 
        o1.user_id,
        CASE WHEN o2.order_date IS NOT NULL THEN 
            ROUND(JULIANDAY(o2.order_date) - JULIANDAY(o1.order_date), 1)
        ELSE NULL END AS days_to_second_order
    FROM ordered_customer_history o1
    LEFT JOIN ordered_customer_history o2 
        ON o1.user_id = o2.user_id AND o2.order_seq = 2
    WHERE o1.order_seq = 1
)
SELECT 
    CASE 
        WHEN days_to_second_order IS NULL THEN '00_Never Repurchased (1-Order Only)'
        WHEN days_to_second_order <= 14 THEN '01_Within 14 Days (Hyper-Engaged)'
        WHEN days_to_second_order <= 30 THEN '02_15 to 30 Days (Standard Habitual)'
        WHEN days_to_second_order <= 60 THEN '03_31 to 60 Days (Delayed Repeat)'
        ELSE '04_Over 60 Days (Late / Long-tail)'
    END AS repurchase_window,
    COUNT(user_id) AS customer_count,
    ROUND(COUNT(user_id) * 100.0 / (SELECT COUNT(*) FROM first_and_second_orders), 2) AS customer_share_pct
FROM first_and_second_orders
GROUP BY repurchase_window;

#3 Net Revenue Retention: +28.5% AOV Expansion Among Core Buyers

Although only 8.57% of January 2024 customers transacted in Month 11, their purchasing behavior transformed significantly. Initial Month 0 AOV was ৳ 2,429.60. By Month 11, surviving customers averaged ৳ 3,191.77 (+28.5% higher basket size). #4 The 60-Day Churn Cliff & One-and-Done Abandonment

Repurchase latency analysis revealed that 42.83% of all registered users made exactly one purchase and never returned. Among customers who did repeat:

  • 5.78% repeated within 14 days (Average: 7.9 days).
  • 11.88% repeated between 15 and 30 days (Average: 22.8 days).
  • 16.89% repeated between 31 and 60 days (Average: 43.3 days).
  • The Drop-off Cliff: After Day 60, organic repurchase probability falls to less than 8%. Any customer unengaged by Day 45 enters terminal churn risk.
